Better Auth can be easily integrated with Waku. Before you start, make sure you have a Better Auth instance configured. If you haven't done that yet, check out the [installation](/docs/installation).

## Create auth instance

Create a file named `auth.ts` in your application. Import Better Auth and create your instance.

<Callout type="warn">
  Make sure to export the auth instance with the variable name `auth` or as a `default` export.
</Callout>

```ts title="src/auth.ts"
import { betterAuth } from "better-auth"

export const auth = betterAuth({
    database: {
        provider: "postgres", //change this to your database provider
        url: process.env.DATABASE_URL, // path to your database or connection string
    }
})
```

## Create API Route

We need to mount the handler to an API route. Create a catch-all route file at `src/pages/_api/api/auth/[...route].ts` and add the following code:

```ts title="src/pages/_api/api/auth/[...route].ts"
import { auth } from "../../../../auth" // Adjust the path as necessary

export const GET = async (request: Request): Promise<Response> => {
  return auth.handler(request)
}

export const POST = async (request: Request): Promise<Response> => {
  return auth.handler(request)
}
```

<Callout type="info">
  You can change the path on your better-auth configuration but it's recommended to keep it as `src/pages/_api/api/auth/[...route].ts`
</Callout>

## Create a client

Create a client instance. Here we are creating `auth-client.ts` file inside the `lib/` directory.

```ts title="src/lib/auth-client.ts"
import { createAuthClient } from "better-auth/react" // make sure to import from better-auth/react

export const authClient = createAuthClient({
    //you can pass client configuration here
})

export type Session = typeof authClient.$Infer.Session // you can infer typescript types from the authClient
```

Once you have created the client, you can use it to sign up, sign in, and perform other actions.
Some of the actions are reactive. The client uses [nano-store](https://github.com/nanostores/nanostores) to store the state and re-render the components when the state changes.

The client also uses [better-fetch](https://github.com/bekacru/better-fetch) to make the requests. You can pass the fetch configuration to the client.

## Server setup

Waku runs its middleware on [Hono](https://hono.dev). The setup below uses Hono's `contextStorage` to keep per-request data, so that cookies Better Auth sets on the server reach the response, and the session is only fetched once per request.

### Cookies and session helpers

When you call a function that sets cookies, like `signInEmail` or `signUpEmail`, from a server action or server component, Better Auth can't set them on Waku's response directly. Instead, a plugin collects them and a middleware adds them to the response.

```ts title="src/auth.ts"
import { betterAuth, type BetterAuthPlugin } from "better-auth";
import { createAuthMiddleware } from "better-auth/api";
import { getContext } from "hono/context-storage";

export const auth = betterAuth({
    //...your config
    plugins: [wakuCookies()] // make sure this is the last plugin in the array // [!code highlight]
})

type AuthEnv = {
  Variables: {
    betterAuthSetCookie?: string[];
    sessionPromise?: ReturnType<typeof auth.api.getSession>;
  };
};

function wakuCookies() {
  return {
    id: "waku-cookies",
    hooks: {
      after: [
        {
          matcher() {
            return true;
          },
          handler: createAuthMiddleware(async (ctx) => {
            const returned = ctx.context.responseHeaders;
            if ("_flag" in ctx && ctx._flag === "router") {
              return;
            }
            if (returned instanceof Headers) {
              const setCookies = returned.getSetCookie();
              if (!setCookies.length) return;
              const c = getContext<AuthEnv>();
              // A single request can make several auth calls
              c.set("betterAuthSetCookie", [
                ...(c.get("betterAuthSetCookie") ?? []),
                ...setCookies,
              ]);
            }
          }),
        },
      ],
    },
  } satisfies BetterAuthPlugin;
}

/**
 * Returns the current session, fetching it at most once per request.
 */
export function getSession() {
  const c = getContext<AuthEnv>();
  const existing = c.get("sessionPromise");
  if (existing) return existing;
  const sessionPromise = auth.api.getSession({ headers: c.req.raw.headers });
  c.set("sessionPromise", sessionPromise);
  return sessionPromise;
}

export function getBetterAuthSetCookie() {
  return getContext<AuthEnv>().get("betterAuthSetCookie");
}
```

Files in `src/middleware` are loaded automatically by Waku's default server adapter. This middleware sets up the request context and adds the collected cookies to the response:

```ts title="src/middleware/auth.ts"
import type { MiddlewareHandler } from "hono";
import { contextStorage } from "hono/context-storage";
import { getBetterAuthSetCookie } from "../auth";

const storage = contextStorage();

const authMiddleware = (): MiddlewareHandler => {
  return (c, next) =>
    storage(c, async () => {
      await next();
      for (const cookie of getBetterAuthSetCookie() ?? []) {
        c.header("set-cookie", cookie, { append: true });
      }
    });
};

export default authMiddleware;
```

### Session refreshes during navigation

Waku streams server component responses, and a client-side navigation's response headers are sent before your components finish rendering. A `getSession()` call in a layout or page can refresh the [cookie cache](/docs/concepts/session-management#cookie-cache) or the session expiry, but those cookies would be dropped.

To avoid this, add a handler interceptor that resolves the session before rendering starts:

```ts title="src/pages/_interceptors/session.ts"
import { tryGetContext } from "hono/context-storage";
import { getRequest, type HandlerInterceptor } from "waku/router/server";
import { getSession } from "../../auth";

const sessionInterceptor: HandlerInterceptor = async (next) => {
  // Static renders at build time have no Hono context, and no session.
  const isRequestRender = tryGetContext() !== undefined;
  // Skip API routes: under `/api/auth`, a refreshed session cookie
  // would override the one sign-out expires.
  const isApiRoute = new URL(getRequest().url).pathname.startsWith("/api/");
  if (isRequestRender && !isApiRoute) {
    await getSession();
  }
  return next();
};

export default sessionInterceptor;
```

Components that call `getSession()` later in the same request get the already-resolved session.

## RSC and Server actions

The `api` object exported from the auth instance contains all the actions that you can perform on the server. Every endpoint made inside Better Auth is invocable as a function, including plugin endpoints.

**Example: Signing in from a server action**

```ts title="src/actions.ts"
"use server"

import { getRequest } from "waku/router/server"
import { auth } from "./auth"

export async function signIn(formData: FormData) {
  await auth.api.signInEmail({
    body: {
      email: String(formData.get("email")),
      password: String(formData.get("password")),
    },
    headers: getRequest().headers,
  })
}
```

The session cookies are added to the response by the middleware above.

**Example: Getting the session in a server component**

```tsx title="src/pages/dashboard.tsx"
import { unstable_redirect as redirect } from "waku/router/server"
import { getSession } from "../auth"

export default async function DashboardPage() {
  const session = await getSession()

  if (!session) {
    redirect("/sign-in")
  }

  return (
    <div>
      <h1>Welcome {session.user.name}</h1>
    </div>
  )
}

export const getConfig = async () => {
  return { render: "dynamic" } as const
}
```

Pages that read the session must use `render: "dynamic"`, so they are rendered per request instead of at build time.

## Optimistic redirects in middleware

In Waku middleware, it's recommended to only check for the existence of a session cookie to handle redirection. This avoids blocking requests by making API or database calls.

You can use the `getSessionCookie` helper from Better Auth for this purpose:

<Callout type="warn">
  The <code>getSessionCookie()</code> function does not automatically reference the auth config specified in <code>auth.ts</code>. Therefore, if you customized the cookie name or prefix, you need to ensure that the configuration in <code>getSessionCookie()</code> matches the config defined in your <code>auth.ts</code>.
</Callout>

```ts title="src/middleware/redirect.ts"
import type { MiddlewareHandler } from "hono"
import { getSessionCookie } from "better-auth/cookies"

const redirectMiddleware = (): MiddlewareHandler => {
  return async (c, next) => {
    const { pathname } = new URL(c.req.url)
    const sessionCookie = getSessionCookie(c.req.raw)
    // THIS IS NOT SECURE!
    // This is the recommended approach to optimistically redirect users
    // We recommend handling auth checks in each page/route
    if (
      !sessionCookie &&
      pathname !== "/" &&
      !pathname.startsWith("/api") &&
      // Client-side navigation: requests `/RSC/...` and can't follow a redirect
      // response. Redirect from the page with `unstable_redirect` instead.
      !pathname.startsWith("/RSC/")
    ) {
      return c.redirect("/", 302)
    }
    await next()
  }
}

export default redirectMiddleware
```

<Callout type="warn">
  **Security Warning:** The `getSessionCookie` function only checks for the
  existence of a session cookie; it does **not** validate it. Relying solely
  on this check for security is dangerous, as anyone can manually create a
  cookie to bypass it. You must always validate the session on your server for
  any protected actions or pages.
</Callout>

<Callout type="info">
  If you have a custom cookie name or prefix, you can pass it to the `getSessionCookie` function.

  ```ts
  const sessionCookie = getSessionCookie(request, {
      cookieName: "my_session_cookie",
      cookiePrefix: "my_prefix"
  })
  ```
</Callout>

Alternatively, you can use the `getCookieCache` helper to get the session object from the [cookie cache](/docs/concepts/session-management#cookie-cache):

```ts title="src/middleware/redirect.ts"
import type { MiddlewareHandler } from "hono"
import { getCookieCache } from "better-auth/cookies"

const redirectMiddleware = (): MiddlewareHandler => {
  return async (c, next) => {
    const { pathname } = new URL(c.req.url)
    const session = await getCookieCache(c.req.raw)
    if (
      !session &&
      pathname !== "/" &&
      !pathname.startsWith("/api") &&
      !pathname.startsWith("/RSC/")
    ) {
      return c.redirect("/", 302)
    }
    await next()
  }
}

export default redirectMiddleware
```

## Example usage

### Sign Up

```ts title="src/components/signup.tsx"
"use client"

import { useState } from "react"
import { authClient } from "../lib/auth-client"

export default function SignUp() {
  const [email, setEmail] = useState("")
  const [name, setName] = useState("")
  const [password, setPassword] = useState("")

  const signUp = async () => {
    await authClient.signUp.email(
      {
        email,
        password,
        name,
      },
      {
        onRequest: (ctx) => {
          // show loading state
        },
        onSuccess: (ctx) => {
          // redirect to home
        },
        onError: (ctx) => {
          alert(ctx.error)
        },
      },
    )
  }

  return (
    <div>
      <h2>
        Sign Up
      </h2>
      <form
        onSubmit={signUp}
      >
        <input
          type="text"
          value={name}
          onChange={(e) => setName(e.target.value)}
          placeholder="Name"
        />
        <input
          type="email"
          value={email}
          onChange={(e) => setEmail(e.target.value)}
          placeholder="Email"
        />
        <input
          type="password"
          value={password}
          onChange={(e) => setPassword(e.target.value)}
          placeholder="Password"
        />
        <button
          type="submit"
        >
          Sign Up
        </button>
      </form>
    </div>
  )
}

```
