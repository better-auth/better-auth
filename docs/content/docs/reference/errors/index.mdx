## Mapping error codes in your app

If `onAPIError.errorURL` points at your own page, map each code to a message with `OAUTH_CALLBACK_ERROR_CODES` and the `OAuthCallbackErrorCode` type from `better-auth/oauth2`. With `satisfies`, leaving a code out is a type error.

```ts title="sign-in-errors.ts"
import {
  OAUTH_CALLBACK_ERROR_CODES,
  type OAuthCallbackErrorCode,
} from "better-auth/oauth2";

const messages = {
  [OAUTH_CALLBACK_ERROR_CODES.STATE_NOT_FOUND]:
    "Your sign-in expired. Please try again.",
  // ...one entry per code
} satisfies Record<OAuthCallbackErrorCode, string>;
```

The `error` parameter can also hold a code the OAuth provider sent, or the `code` of an `APIError` thrown from a hook. Better Auth passes both through unchanged, so keep a fallback message for codes outside the type.
