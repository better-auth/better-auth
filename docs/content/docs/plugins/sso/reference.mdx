This reference describes the options, provider fields, endpoints, and database schema of `@better-auth/sso`.

## Plugin options

Pass these options to `sso()`. All of them are optional.

### Users and accounts

| Option                      | Type                                                       | Default | Description                                                                                                                                                                                                                                                           |
| --------------------------- | ---------------------------------------------------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `resolveUser`               | `(input, context) => Awaitable<SSOUserResolution>`         | —       | Maps a verified provider identity to a user on every SSO sign-in. Return `continue`, `link`, or `reject`. Runs in a database transaction, so the adapter needs native transaction support. See [Resolve SSO Users](/docs/plugins/sso/provisioning#resolve-sso-users). |
| `provisionUser`             | `({ user, userInfo, token, provider }) => Awaitable<void>` | —       | Runs after a new user signs in through SSO, before organization assignment. A thrown error aborts the sign-in. See [User provisioning](/docs/plugins/sso/provisioning#user-provisioning).                                                                             |
| `provisionUserOnEveryLogin` | `boolean`                                                  | `false` | Runs `provisionUser` on every sign-in, not only the first. Keep the callback idempotent.                                                                                                                                                                              |
| `organizationProvisioning`  | `object`                                                   | —       | Adds SSO users to the organization the provider is linked to. See [Organization provisioning](/docs/plugins/sso/provisioning#organization-provisioning).                                                                                                              |
| `defaultOverrideUserInfo`   | `boolean`                                                  | `false` | Default `overrideUserInfo` for OIDC providers registered without it.                                                                                                                                                                                                  |
| `disableImplicitSignUp`     | `boolean`                                                  | `false` | Stops SSO sign-in from creating new users. For OIDC, pass `requestSignUp: true` at sign-in to allow it. SAML ignores `requestSignUp`. See [Sign in](/docs/plugins/sso#sign-in).                                                                                       |
| `trustEmailVerified`        | `boolean`                                                  | `false` | **Deprecated.** Reads the provider's email verified flag through `mapping.emailVerified`. Otherwise every SSO user has `emailVerified: false`.                                                                                                                        |

<Callout type="warn">
  `trustEmailVerified` can lead to account takeover when users can register their own providers, because any provider can then assert a verified email. Use [domain verification](/docs/plugins/sso/domain-verification#domain-verification) or `resolveUser` instead.
</Callout>

<Accordions>
  <Accordion title="organizationProvisioning options">
    `disabled` <span className="opacity-70">`boolean`</span>

    Turns off organization assignment. Defaults to `false`.

    `defaultRole` <span className="opacity-70">`"member" | "admin"`</span>

    Role given to new members. Defaults to `"member"`.

    `getRole` <span className="opacity-70">`({ user, userInfo, token, provider }) => Promise<"member" | "admin">`</span>

    Picks the role per user. Takes precedence over `defaultRole`.
  </Accordion>
</Accordions>

### Providers

| Option                  | Type                                                                                               | Default | Description                                                                                                                                                                                                                                        |
| ----------------------- | -------------------------------------------------------------------------------------------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `defaultSSO`            | `array`                                                                                            | —       | Providers defined in code. They are checked before the database, by `providerId` or by email domain at sign-in, and domain verification treats them as verified. See [Configure providers in code](/docs/plugins/sso#configure-providers-in-code). |
| `providersLimit`        | `number \| (user) => Awaitable<number>`                                                            | `10`    | Maximum providers each user can register. `0` disables registration. See [Register a provider](/docs/plugins/sso#register-a-provider).                                                                                                             |
| `redirectURI`           | `string`                                                                                           | —       | One OIDC callback for every provider, as a path or a full URL. See [Shared Redirect URI](/docs/plugins/sso/oidc#shared-redirect-uri).                                                                                                              |
| `resolvePrivateKey`     | `({ providerId, keyId, issuer }) => Promise<{ privateKeyJwk?, privateKeyPem?, kid?, algorithm? }>` | —       | Returns the signing key for `private_key_jwt`, so keys stay out of the database. Registering a `private_key_jwt` provider fails without it. See [Token endpoint authentication](/docs/plugins/sso/oidc#token-endpoint-authentication).             |
| `guardProviderMutation` | `(input, context) => Awaitable<void>`                                                              | —       | Runs before a stored provider is updated or deleted. Throw to reject the change, which returns a conflict. Needs native transaction support. See [Manage providers](/docs/plugins/sso#manage-providers).                                           |
| `domainVerification`    | `{ enabled?: boolean; tokenPrefix?: string }`                                                      | —       | Requires DNS proof of domain ownership before a provider can sign users in. `tokenPrefix` defaults to `"better-auth-token"`. See [Domain verification](/docs/plugins/sso/domain-verification#domain-verification).                                 |

<Accordions>
  <Accordion title="defaultSSO entry">
    `providerId` <span className="opacity-70">`string`</span>

    Required. A registered provider cannot reuse this id.

    `domain` <span className="opacity-70">`string`</span>

    Required. A bare email domain such as `example.com`, or several separated by commas.

    `oidcConfig` <span className="opacity-70">`OIDCConfig`</span>

    The stored OIDC shape. `issuer`, `discoveryEndpoint`, and `pkce` are required here. This is the only place `allowIdpInitiated` takes effect.

    `samlConfig` <span className="opacity-70">`SAMLConfig`</span>

    The stored SAML shape. `issuer` is required here.

    `privateKey` <span className="opacity-70">`{ privateKeyJwk?: JsonWebKey; privateKeyPem?: string }`</span>

    Signing key for `private_key_jwt`. It is never stored in the database.
  </Accordion>
</Accordions>

### SAML

Set these under `saml`.

| Option                         | Type      | Default  | Description                                                                                                                                                                                              |
| ------------------------------ | --------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `enableInResponseToValidation` | `boolean` | `true`   | Matches each response to a stored AuthnRequest. See [InResponseTo validation](/docs/plugins/sso/saml-security#inresponseto-validation).                                                                  |
| `allowIdpInitiated`            | `boolean` | `false`  | Accepts unsolicited responses. Applies only while InResponseTo validation is on. See [IdP-initiated SSO](/docs/plugins/sso/saml#idp-initiated-sso).                                                      |
| `requestTTL`                   | `number`  | `300000` | Lifetime of an AuthnRequest record, in milliseconds.                                                                                                                                                     |
| `clockSkew`                    | `number`  | `300000` | Tolerance for assertion timestamps, in milliseconds. See [Timestamp validation](/docs/plugins/sso/saml-security#timestamp-validation).                                                                   |
| `requireTimestamps`            | `boolean` | `false`  | Rejects assertions without `NotBefore` and `NotOnOrAfter`.                                                                                                                                               |
| `algorithms`                   | `object`  | —        | Rules for signature and encryption algorithms. See [Algorithm validation](/docs/plugins/sso/saml-security#algorithm-validation).                                                                         |
| `maxResponseSize`              | `number`  | `262144` | Largest accepted SAML response, in bytes. See [Size limits](/docs/plugins/sso/saml-security#size-limits).                                                                                                |
| `maxMetadataSize`              | `number`  | `102400` | Largest accepted IdP or SP metadata XML, in bytes. Also enforced when a provider is saved.                                                                                                               |
| `idpInitiatedCallbackUrl`      | `string`  | —        | Fallback redirect for IdP-initiated responses when no provider callback applies. An absolute URL or a path starting with `/`. See [ACS and callback URLs](/docs/plugins/sso/saml#acs-and-callback-urls). |
| `enableSingleLogout`           | `boolean` | `false`  | Adds the Single Logout endpoints and advertises them in SP metadata. See [Single Logout](/docs/plugins/sso/saml#single-logout).                                                                          |
| `logoutRequestTTL`             | `number`  | `300000` | Lifetime of a LogoutRequest record, in milliseconds.                                                                                                                                                     |
| `wantLogoutRequestSigned`      | `boolean` | `false`  | Requires signed LogoutRequests from the IdP.                                                                                                                                                             |
| `wantLogoutResponseSigned`     | `boolean` | `false`  | Requires signed LogoutResponses from the IdP.                                                                                                                                                            |

<Accordions>
  <Accordion title="algorithms options">
    `onDeprecated` <span className="opacity-70">`"reject" | "warn" | "allow"`</span>

    What to do when a response or a saved provider uses SHA-1, RSA1\_5, or 3DES. Defaults to `"warn"`.

    `allowedSignatureAlgorithms` <span className="opacity-70">`string[]`</span>

    Accepts only these signature algorithm URIs in responses and in `samlConfig.signatureAlgorithm`. When set, it replaces the deprecated check for signatures.

    `allowedDigestAlgorithms` <span className="opacity-70">`string[]`</span>

    Accepts only these digest algorithms in `samlConfig.digestAlgorithm` when a provider is saved.

    `allowedKeyEncryptionAlgorithms` <span className="opacity-70">`string[]`</span>

    Accepts only these key encryption algorithm URIs for encrypted assertions.

    `allowedDataEncryptionAlgorithms` <span className="opacity-70">`string[]`</span>

    Accepts only these data encryption algorithm URIs for encrypted assertions.
  </Accordion>
</Accordions>

## Provider configuration

### Registration body

The body of `POST /sso/register`. `POST /sso/update-provider` takes `providerId` plus optional `issuer`, `domain`, `oidcConfig`, `samlConfig`, and additional fields. See [Manage providers](/docs/plugins/sso#manage-providers).

| Field              | Type      | Default                   | Description                                                                                                                                                                                                                                     |
| ------------------ | --------- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `providerId`       | `string`  | —                         | Required and unique. Ids of built-in, social, trusted, or `defaultSSO` providers are rejected with 422.                                                                                                                                         |
| `issuer`           | `string`  | —                         | Required URL. The OIDC issuer, or the SAML SP entity ID.                                                                                                                                                                                        |
| `domain`           | `string`  | —                         | Required. A bare email domain, or several separated by commas.                                                                                                                                                                                  |
| `organizationId`   | `string`  | —                         | Links the provider to an organization. The caller must be a member, and an owner or admin when the organization plugin is enabled. See [Link a provider to an organization](/docs/plugins/sso/provisioning#link-a-provider-to-an-organization). |
| `overrideUserInfo` | `boolean` | `defaultOverrideUserInfo` | OIDC only. Updates the user's name, image, and additional fields from the provider on every sign-in.                                                                                                                                            |
| `oidcConfig`       | `object`  | —                         | OIDC settings. Pass this or `samlConfig`.                                                                                                                                                                                                       |
| `samlConfig`       | `object`  | —                         | SAML settings. Pass this or `oidcConfig`.                                                                                                                                                                                                       |
| Additional fields  | —         | —                         | Fields from `schema.ssoProvider.additionalFields`.                                                                                                                                                                                              |

### oidcConfig

See [Register an OIDC Provider](/docs/plugins/sso/oidc#register-an-oidc-provider).

| Field                         | Type                                                                 | Default                                            | Description                                                                                                                                                                                  |
| ----------------------------- | -------------------------------------------------------------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `clientId`                    | `string`                                                             | —                                                  | Required.                                                                                                                                                                                    |
| `clientSecret`                | `string`                                                             | —                                                  | Required for `client_secret_basic` and `client_secret_post`.                                                                                                                                 |
| `discoveryEndpoint`           | `string`                                                             | `{issuer}/.well-known/openid-configuration`        | Discovery document URL. See [OIDC Discovery](/docs/plugins/sso/oidc#oidc-discovery).                                                                                                         |
| `skipDiscovery`               | `boolean`                                                            | `false`                                            | Skips discovery at registration. Then pass `authorizationEndpoint`, `tokenEndpoint`, and `jwksEndpoint`.                                                                                     |
| `authorizationEndpoint`       | `string`                                                             | Discovered                                         | Authorization endpoint URL.                                                                                                                                                                  |
| `tokenEndpoint`               | `string`                                                             | Discovered                                         | Token endpoint URL.                                                                                                                                                                          |
| `userInfoEndpoint`            | `string`                                                             | Discovered                                         | UserInfo endpoint URL.                                                                                                                                                                       |
| `jwksEndpoint`                | `string`                                                             | Discovered                                         | JWKS URL for ID Token verification.                                                                                                                                                          |
| `tokenEndpointAuthentication` | `"client_secret_basic" \| "client_secret_post" \| "private_key_jwt"` | Discovered, else `client_secret_basic`             | Client authentication at the token endpoint. See [Token endpoint authentication](/docs/plugins/sso/oidc#token-endpoint-authentication).                                                      |
| `privateKeyId`                | `string`                                                             | —                                                  | Key id passed to `resolvePrivateKey` and sent as `kid`.                                                                                                                                      |
| `privateKeyAlgorithm`         | `string`                                                             | `"RS256"`                                          | Signing algorithm for `private_key_jwt`.                                                                                                                                                     |
| `scopes`                      | `string[]`                                                           | `["openid", "email", "profile", "offline_access"]` | Scopes to request.                                                                                                                                                                           |
| `pkce`                        | `boolean`                                                            | `true`                                             | Sends a PKCE challenge ([RFC 7636](https://datatracker.ietf.org/doc/html/rfc7636)).                                                                                                          |
| `overrideUserInfo`            | `boolean`                                                            | —                                                  | Where the top-level `overrideUserInfo` is stored. Ignored at registration, where you set the top-level field. Set it here on update.                                                         |
| `mapping`                     | `object`                                                             | —                                                  | Claim names to read. See [Mapping](/docs/plugins/sso/oidc#mapping).                                                                                                                          |
| `allowIdpInitiated`           | `boolean`                                                            | `false`                                            | Accepts callbacks without `state`. Honored only on `defaultSSO` entries, because registration and update drop it. See [IdP-initiated sign-in](/docs/plugins/sso/oidc#idp-initiated-sign-in). |

| `idpInitiatedCallbackUrl` | `string`             | —        | Fallback for IdP-initiated responses, as an absolute URL or a `/path`. Takes precedence over the plugin option. | `idpMetadata`             | `object`             | —        | Required. | `authnRequestsSigned`     | `boolean`            | `false`  | Signs AuthnRequests. Sign-in returns 400 without a private key. | `signatureAlgorithm`      | `string`             | —        | Signature algorithm URI or short form such as `rsa-sha256`. | `digestAlgorithm`         | `string`             | —        | Digest algorithm URI or short form such as `sha256`. Checked against `saml.algorithms` when the provider is saved.                                                                                                                                                           |
| `identifierFormat`        | `string`             | —        | NameID format advertised in generated SP metadata.                                                                                                                                                                                                                           |
| `privateKey`              | `string`             | —        | SP signing key, used when `spMetadata.privateKey` is not set.                                                                                                                                                                                                                |
| `mapping`                 | `object`             | —        | Attribute names to read. ## Endpoints

Paths are relative to your auth base path, `/api/auth` by default.

| Method       | Path                                 | Auth                 | Purpose                                                      |
| ------------ | ------------------------------------ | -------------------- | ------------------------------------------------------------ |
| `POST`       | `/sso/register`                      | Session              | Register a provider.                                         |
| `POST`       | `/sign-in/sso`                       | None                 | Start an SSO sign-in.                                        |
| `GET`        | `/sso/callback/:providerId`          | None                 | OIDC callback.                                               |
| `GET`        | `/sso/callback`                      | None                 | Shared OIDC callback, used with `redirectURI`.               |
| `GET` `POST` | `/sso/saml2/sp/acs/:providerId`      | IdP, no origin check | SAML Assertion Consumer Service.                             |
| `GET`        | `/sso/saml2/sp/metadata?providerId=` | None                 | SP metadata as XML.                                          |
| `GET` `POST` | `/sso/saml2/sp/slo/:providerId`      | IdP, no origin check | SAML Single Logout, with `enableSingleLogout`.               |
| `POST`       | `/sso/saml2/logout/:providerId`      | Session              | Start SP-initiated Single Logout, with `enableSingleLogout`. |
| `GET`        | `/sso/providers`                     | Session              | List the providers you can manage.                           |
| `GET`        | `/sso/get-provider`                  | Session              | Get one provider by `providerId`.                            |
| `POST`       | `/sso/update-provider`               | Session              | Update a provider.                                           |
| `POST`       | `/sso/delete-provider`               | Session              | Delete a provider and its linked accounts.                   |
| `POST`       | `/sso/request-domain-verification`   | Session              | Get a DNS verification token, with domain verification.      |
| `POST`       | `/sso/verify-domain`                 | Session              | Check the DNS record, with domain verification.              |

For error codes, see [Discovery errors](/docs/plugins/sso/oidc#discovery-errors) and [SAML security](/docs/plugins/sso/saml-security).

## Additional provider fields

Add columns to `ssoProvider` with `schema.ssoProvider.additionalFields`.

```ts title="auth.ts"
sso({
  schema: {
    ssoProvider: {
      additionalFields: {
        displayName: { type: "string", required: true }, // [!code highlight]
      },
    },
  },
});
```

Pass the field when you register or update a provider, for example `displayName: "Acme"`. Fields with `input: false` are rejected in requests, and fields with `returned: false` are left out of client types. Pass the same `schema` to `ssoClient()` so client types match.

<Callout type="warn">
  Startup throws when a field uses a built-in name (`id`, `issuer`, `oidcConfig`, `samlConfig`, `userId`, `providerId`, `organizationId`, `domain`, `domainVerified`) or a response name (`type`, `spMetadataUrl`, `redirectURI`, `domainVerificationToken`), or when its `fieldName` maps to a built-in column.
</Callout>

### Verification records

The plugin also writes short-lived records to the verification table, or to secondary storage when one is configured.

| Identifier prefix             | Stores                                                |
| ----------------------------- | ----------------------------------------------------- |
| `saml-authn-request:`         | AuthnRequest IDs for InResponseTo validation          |
| `saml-used-assertion:`        | Assertion IDs already consumed, for replay protection |
| `saml-session:`               | NameID and SessionIndex for Single Logout             |
| `saml-session-by-id:`         | Lookup from a session ID to its SAML session record   |
| `saml-logout-request:`        | LogoutRequest IDs for SP-initiated Single Logout      |
| `_{tokenPrefix}-{providerId}` | Domain verification tokens                            |

Expired rows can be deleted.
