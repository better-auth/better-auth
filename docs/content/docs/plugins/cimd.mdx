`OAuth2` `MCP`

The [Client ID Metadata Document draft-00](https://datatracker.ietf.org/doc/html/draft-ietf-oauth-client-id-metadata-document-00) lets clients identify themselves to your authorization server without prior registration. Instead of sending a pre-registered `client_id`, the client sends the HTTPS URL of a metadata document it hosts. Your server fetches that document, validates it, and creates or refreshes a client record. The record's authentication behavior is determined by `token_endpoint_auth_method`.

This is the mechanism [MCP](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/client-registration#client-id-metadata-documents) uses so authorization servers can discover clients on the fly.

The plugin extends [`@better-auth/oauth-provider`](./oauth-provider) by contributing a `ClientDiscovery` entry through its extension surface, so every OAuth endpoint that authenticates a client (authorize, token, introspect, revoke, userinfo, PAR, logout) works seamlessly with URL-format `client_id` values.

## Installation

<Steps>
  <Step>
    ### Install the plugin

    ```package-install
    @better-auth/cimd
    ```
  </Step>

  <Step>
    ### Add the plugin to the server

    Install `cimd()` alongside `oauthProvider()`. The plugin requires `oauth-provider` to be present and will throw at startup if it is missing.

    ```ts title="auth.ts"
    import { betterAuth } from "better-auth";
    import { jwt } from "better-auth/plugins";
    import { oauthProvider } from "@better-auth/oauth-provider";
    import { cimd } from "@better-auth/cimd"; // [!code highlight]

    export const auth = betterAuth({
      plugins: [
        jwt(),
        oauthProvider({
          loginPage: "/login",
          consentPage: "/consent",
          scopes: ["openid", "profile", "email", "offline_access"],
        }),
        cimd(), // [!code highlight]
      ],
    });
    ```
  </Step>
</Steps>

## Usage

Once installed, your authorization server accepts an HTTPS URL as a `client_id` on any OAuth endpoint. The first time a URL `client_id` is seen, the server fetches the metadata document and creates a client record using the document's `token_endpoint_auth_method`. Valid documents are cached according to their HTTP cache headers, with `refreshRate` as the maximum and fallback lifetime. A stale document is revalidated before the OAuth request continues.

```http
GET /api/auth/oauth2/authorize?
    response_type=code
    &client_id=https%3A%2F%2Fmcp-client.example.com%2Fclient-metadata.json
    &redirect_uri=https%3A%2F%2Fmcp-client.example.com%2Fcallback
    &scope=openid
    &code_challenge=...
    &code_challenge_method=S256
```

The CIMD client is stored in the standard `oauthClient` table with its URL as the `clientId`, so it shows up in the same queries and admin UIs as any other registered client.

### Discovery metadata

The plugin advertises `client_id_metadata_document_supported: true` on the `/.well-known/oauth-authorization-server` and `/.well-known/openid-configuration` responses. MCP clients and other spec-aware consumers use that flag to decide whether to attempt a URL `client_id`.

## Configuration

```ts title="auth.ts"
cimd({
  refreshRate: "10m",
  maxCacheEntries: 1000,
  originBoundFields: ["post_logout_redirect_uris", "client_uri"],
  allowFetch(url) {
    return new URL(url).hostname.endsWith(".trusted.example");
  },
  onClientCreated({ client, metadata, ctx }) {
    // assign trust levels, prefetch logos, populate audit log, etc.
  },
  onClientRefreshed({ client, metadata, ctx }) {
    // detect field changes, update derived data, etc.
  },
});
```

## Metadata document requirements

The fetched document must satisfy both §3 and §4.1 of draft-00. Key rules enforced by the plugin:

* `client_id` in the body must equal the fetch URL byte-for-byte.
* HTTPS only. Loopback URLs (`localhost`, `127.0.0.0/8`, `::1`, `*.localhost`), including plain HTTP, are accepted only when `allowLoopback` is enabled for local development.
* No fragments, credentials, or `./` / `../` dot segments in the URL.
* A path component is required (`https://example.com/` is rejected; `https://example.com/meta.json` is accepted).
* `client_name` is required and cannot be blank.
* `client_secret`, `client_secret_expires_at`, `client_id_issued_at`, `resources`, and server-owned registration controls are prohibited.
* `token_endpoint_auth_method` must be `"none"` or `"private_key_jwt"`. Symmetric methods (`client_secret_post`, `client_secret_basic`, `client_secret_jwt`) are rejected.
* `redirect_uris` is required and must be a non-empty array of absolute HTTP(S) URIs or authority-free private-use URIs with a well-formed reverse-domain scheme, such as `com.example.app:/callback`.
* `application_type` may be `web` or `native`. When omitted, the database keeps it as `null` and redirect validation accepts the safe union of both application types: non-loopback HTTPS, exact loopback HTTP, or an authority-free private-use URI with a well-formed reverse-domain scheme.
* `grant_types` (if present) must be a subset of `["authorization_code", "refresh_token"]`.
* `response_types` (if present) must be a subset of `["code"]`.
* The complete shared OAuth client metadata schema is parsed before CIMD-specific restrictions are applied. Malformed known fields are rejected instead of being cast or silently discarded.
* Extension metadata may be retained, but server-owned fields such as `disabled`, `skip_consent`, `enable_end_session`, `require_pkce`, `reference_id`, and `user_id` are rejected before persistence.

### Example document

```json title="https://mcp-client.example.com/client-metadata.json"
{
  "client_id": "https://mcp-client.example.com/client-metadata.json",
  "client_name": "Example MCP Client",
  "client_uri": "https://mcp-client.example.com",
  "redirect_uris": [
    "https://mcp-client.example.com/callback",
    "http://127.0.0.1:3000/callback"
  ],
  "token_endpoint_auth_method": "none",
  "grant_types": ["authorization_code", "refresh_token"],
  "response_types": ["code"],
  "scope": "openid profile email offline_access"
}
```

## Security

The plugin ships defense in depth against common abuses of unauthenticated client discovery:

* **SSRF protection (server-side request forgery).** Private, reserved, link-local, unspecified, cloud-metadata, and tunneled IP literals are rejected syntactically; known special-use hostnames are rejected too, and loopback is opt-in. The runtime-neutral plugin does not resolve DNS. Use `allowFetch` and your runtime network policy to reject public hostnames that resolve or rebind to private addresses.
* **Fetch hardening.** 5s timeout, 5 KB response size limit (UTF-8 byte-counted), no redirect following, `Accept: application/json` only.
* **Origin binding.** Fields in `originBoundFields` must share the `client_id` origin. Redirect URIs are not origin-bound by default; the authorization endpoint still requires the requested `redirect_uri` to match a registered value exactly.
* **No secrets from documents.** Symmetric authentication methods and `client_secret` fields are rejected before anything is written to the database.
* **Server-owned field rejection.** `disabled`, `skip_consent`, `enable_end_session`, `require_pkce`, resource links, and server-issued identifiers cannot be set, escalated, or weakened from an external document.
* **Admin overrides survive refreshes.** `disabled`, `skipConsent`, and `enableEndSession` set by an admin on a persisted CIMD client are preserved across stale refreshes: the document can't silently undo a revoke or consent override.
* **Public key validation.** `private_key_jwt` requires a structurally valid public JWKS or a public HTTPS `jwks_uri`. A same-origin `jwks_uri` is trusted by the CIMD binding without adding unrelated `trustedOrigins`.

## Operational notes

* **Refresh runs on the OAuth hot path.** When the cached document is stale, the next OAuth request awaits revalidation before completing. `Cache-Control`, `Expires`, `ETag`, and `Last-Modified` are honored; `refreshRate` caps origin freshness and supplies the fallback lifetime. `no-cache` forces revalidation and `no-store` prevents cache insertion.
* **Refresh fails closed.** A failed network request, invalid replacement, or persistence failure leaves the previous database and cache state intact but rejects the current OAuth request. Stale metadata is never served after a failed refresh; a later request retries.
* **Consent display.** A consent UI must display both the Client ID hostname and the redirect hostname, or the full private-use redirect URI. The signed consent handoff includes the exact `client_id` and `redirect_uri` for this purpose.
* **Loopback is opt-in.** Loopback `client_id` URLs (`localhost`, `127.0.0.0/8`, `::1`, `*.localhost`), including plain HTTP, are fetched only when `allowLoopback` is set. Leave it off in production so the server never fetches its own loopback interface. Loopback `redirect_uris` remain allowed for native/desktop flows regardless.

## Composition with `clientDiscovery`

Under the hood, `cimd()` contributes a `ClientDiscovery` entry through `oauthProvider`'s extension surface. If you prefer to wire it explicitly, or want to compose CIMD with other discovery implementations, use the `cimdClientDiscovery` factory:

```ts title="auth.ts"
import { oauthProvider } from "@better-auth/oauth-provider";
import { cimdClientDiscovery } from "@better-auth/cimd";

export const auth = betterAuth({
  plugins: [
    jwt(),
    oauthProvider({
      extensions: [
        {
          clientDiscovery: [
            cimdClientDiscovery({ refreshRate: "60m" }),
            // other discovery implementations can go here
          ],
        },
      ],
    }),
  ],
});
```

The `clientDiscovery` extension field accepts a single `ClientDiscovery` or an array. Entries are consulted in order after the database lookup in `getClient()`; the first entry whose `matches()` returns `true` and whose `resolve()` returns a non-null client wins. Each entry can also contribute `discoveryMetadata` that the server merges into `/.well-known/oauth-authorization-server` and `/.well-known/openid-configuration` responses.
