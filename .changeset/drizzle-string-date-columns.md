"@better-auth/drizzle-adapter": patch
---

Drizzle schemas that store dates in string columns now work: `timestamp({ mode: "string" })`, MySQL `datetime({ mode: "string" })`, and SQLite `text()`, including on Cloudflare D1. Before, the adapter passed a JavaScript `Date` to those columns. Drivers such as postgres-js, better-sqlite3 and D1 rejected it, so email sign-up, social sign-in and session refresh failed. Filtering on those columns, for example when listing sessions, failed the same way. Better Auth now writes these dates as UTC text and reads a value without a time zone as UTC.

If your server's time zone is not UTC and you use node-postgres or mysql2 with a string column that has no time zone, existing rows were written in the server's local time. They now read back shifted by the server's UTC offset, so sessions and verification codes created before the upgrade can expire early or late. Schemas generated by the CLI use date columns and are unaffected.
