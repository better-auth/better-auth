A new opt-in `metadataStaleIfError` option keeps a known Client ID Metadata Document client working while its metadata host is briefly down. When refreshing a stored client's document times out, fails to connect with a known network error code, or gets an HTTP 500, 502, 503, or 504 response, the stored client is served with a warning for up to the configured time (at most 24 hours) after it was last validated, and the document is fetched again at most once a minute. On runtimes whose fetch errors carry no error code, only the timeout and those four statuses count. A `metadataFetchPolicy` limit or the Node transport's DNS lookup limit serves the stored client only within 5 minutes of such a failure, and otherwise answers `temporarily_unavailable` as it does without the option. An HTTP 4xx response, an invalid document, a refreshed document that the OAuth provider refuses to save, or a URL that `isMetadataDocumentUrlAllowed` refuses still fails as before, and also stops that instance from serving the stored client until a refresh succeeds. Any other error from the transport, such as an unresolvable host or a refused address, still fails as before without stopping stale serving. For `private_key_jwt` clients, cached `jwks_uri` keys are used the same way when fetching them fails transiently. Without the option, nothing changes.
