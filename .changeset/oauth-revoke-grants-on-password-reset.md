A password reset that revokes sessions (`emailAndPassword.revokeSessionsOnPasswordReset`) and `/revoke-sessions` now revoke the user's stored opaque access tokens and refresh tokens, including `offline_access` refresh tokens, when at least one live session is deleted. In-flight authorization-code exchanges and refresh rotations cannot leave active tokens behind, and each request sweeps a user's tokens once while retaining per-session logout delivery. A password reset for a user with no live session does not revoke these grants. Self-contained JWT access tokens are not directly revoked and can remain valid until expiry; introspection and userinfo still enforce session liveness for session-bound tokens. Token sweep write failures are reported to the caller after attempting both sweeps, even with background delivery configured; already-applied password and session changes are not rolled back. Best-effort logout notification delivery is still attempted for sessions confirmed ended when a sweep fails. Notification-planning read failures are logged but cannot bypass the required sweep. A normal sign-out keeps `offline_access` refresh tokens.
